Bloc 1 · 0:08 à 0:42

Comment une page arrive jusqu’à toi

Trois mots à installer, pas un cours réseau. IP, nom de site, client et serveur. Tout le reste (DNS, HTTP, navigateur) sert ces trois mots.

1. Internet n’est pas « le wifi »

À dire

« Le wifi, c’est juste le dernier mètre, entre toi et la box. Internet, c’est des millions d’ordinateurs reliés. Ta page n’est pas “dans le téléphone”. Elle est sur une machine quelque part, et ton téléphone la demande. »

Analogie quartier : tu veux aller chez Awa. Tu n’as pas besoin de connaître toutes les rues du pays. Tu as un nom (Chez Awa) et une adresse (12, rue du Marché). Internet fait la même chose.

2. Client et serveur

Le client

Celui qui demande. Ton navigateur (Chrome), l’app WhatsApp, ton téléphone. Il envoie une requête et attend une réponse.

Le serveur

Celui qui répond. Un ordinateur allumé en permanence, avec les fichiers de la page. Il écoute, il envoie le HTML, les images, le CSS.

À dire « Dans un resto : toi tu commandes (client), la cuisine prépare (serveur), le plateau arrive devant toi (le navigateur dessine la page). Si la cuisine est fermée, tu as une erreur. Si le plat n’existe pas, tu as un 404. »
Piège fréquent « Serveur » ne veut pas dire « la personne du support ». C’est une machine (ou un programme) qui attend des demandes. Un même ordinateur peut être client le matin et héberger un petit serveur le soir.

3. L’adresse IP

À dire

Une adresse IP identifie une machine sur le réseau, comme un numéro de téléphone identifie une ligne.

Exemple IPv4 : 8.8.8.8 : quatre nombres entre 0 et 255, séparés par des points. C’est lisible pour une machine, pénible pour un humain. Personne ne retient 142.250.200.78 pour aller sur Google.

Démo (2 min)
  1. Ouvre un onglet, tape https://example.com.
  2. Dis : « cette page vit sur un serveur. Pour l’atteindre, le réseau a besoin de son IP. »
  3. Optionnel si le temps le permet : clique-droit → Inspecter → onglet Réseau → recharge. Montre une ligne, le statut 200. « 200 = le serveur a dit OK, voici le fichier. »

4. Le nom de site et le DNS

À dire

Le nom de domaine (google.com, whatsapp.com) est le nom de la boutique. Facile à retenir, facile à dire au marché.

Le DNS (Domain Name System) est l’annuaire. Tu demandes : « quelle est l’IP de google.com ? » L’annuaire répond une IP. Ensuite seulement, ton navigateur va frapper à la bonne porte.

Analogie : tu dis au taxi « emmène-moi chez Awa ». Le taxi ne connaît pas Awa. Il demande à quelqu’un l’adresse, puis il y va. Le DNS, c’est cette personne.

5. Une URL, c’est une phrase précise

Prends : https://wa.me/22890123456

MorceauExempleRôle
Protocolehttps://Comment on parle au serveur. Le S = chiffré (cadenas).
Nom d’hôtewa.meLe nom du site. Le DNS le transforme en IP.
Chemin/22890123456Quelle ressource précise on veut.
Requête (optionnel)?text=BonjourUn paramètre. Ici, le message prérempli.
À dire « HTTP est la langue de la commande. HTTPS est la même langue, dans une enveloppe fermée. Pour une vitrine et un lien WhatsApp, on vise toujours https. On ne met jamais un mot de passe dans une page. Ça, ce sera le soir cyber. »

6. Le voyage complet, dans l’ordre

1. Tu tapes le nom 2. DNS → IP 3. Client contacte le serveur 4. Serveur envoie le HTML 5. Le navigateur dessine
À dire, lentement, en pointant le schéma
  1. Tu écris mon-site.com (ou tu cliques un lien).
  2. Le DNS traduit le nom en IP.
  3. Ton navigateur (client) envoie une requête au serveur : « donne-moi la page ».
  4. Le serveur répond : fichier HTML, puis CSS, puis images.
  5. Le navigateur assemble et affiche. Toi tu vois « la page ». Tu ne vois pas l’IP.

Si l’étape 2 échoue : « site introuvable ». Si l’étape 4 échoue : page blanche, 404, ou délai dépassé.

Lien avec le mini-projet Ce soir, leur vitrine vivra d’abord sur leur ordinateur (fichier local). Le client et le serveur sont la même machine. Le voyage est le même, en miniature. Plus tard on pourra l’héberger ; ce n’est pas le sujet du soir.

Bloc 2 · 0:47 à 1:22

Écrire une page HTML et un peu de CSS

Après la pause. Tu codes en live, ils recopient. Pas de slides : un fichier vide et tes doigts. Parle plus lentement que d’habitude.

1. HTML, c’est la structure

À dire

« HTML veut dire HyperText Markup Language. Ce n’est pas un roman : c’est une ossature. Tu poses des balises, le navigateur comprend le rôle de chaque morceau : ceci est un titre, ceci est un paragraphe, ceci est un lien. »

Analogie : HTML = les murs et les pièces. CSS = la peinture, les rideaux, l’alignement. Sans HTML, le CSS n’a rien à peindre.

2. Une balise, comment elle s’écrit

<p>Ceci est un paragraphe.</p>
  • <p> ouvre. </p> ferme. Le slash ferme.
  • Ce qu’il y a au milieu est le contenu, visible.
  • Quelques balises n’ont pas de contenu : <img>, <meta>.
À marteler Minuscules. Balises fermées. Accents OK dans le texte, pas dans les noms de balises. Un oubli de </p> casse souvent la suite de la page.

3. Le squelette obligatoire

Toute page commence comme ça. Fais-les le taper une fois, pas copier-coller silencieux.

<!DOCTYPE html>
<html lang="fr">
  <head>
    <meta charset="UTF-8" />
    <title>Ma vitrine</title>
    <style>
      /* le CSS viendra ici */
    </style>
  </head>
  <body>
    <h1>Mon prénom</h1>
    <p>Une phrase sur moi.</p>
  </body>
</html>
LignePourquoi elle est là
<!DOCTYPE html>Dit au navigateur : c’est du HTML moderne.
lang="fr"Page en français (accents, accessibilité).
<head>Infos pour le navigateur, pas le texte principal.
charset="UTF-8"Sans ça, les accents cassent (é → Ã©).
<title>Le nom de l’onglet.
<body>Ce que l’humain voit.

À dire : le lien, c’est le cœur

Un lien a une adresse dans href :

<a href="https://wa.me/22890123456">Écrire sur WhatsApp</a>
  • Le numéro : indicatif pays + numéro, sans + ni espaces. Togo = 228, Bénin = 229, Burkina = 226, Côte d’Ivoire = 225, Sénégal = 221.
  • Message prérempli : ?text=Bonjour (les espaces deviennent %20 si besoin).
  • target="_blank" n’est pas obligatoire ce soir.

5. Un peu de CSS : trois idées, pas un framework

À dire « Une règle CSS a trois morceaux : qui (sélecteur), quoi (propriété), combien (valeur). » 
body {
  font-family: sans-serif;
  background: #efe6d6;
  color: #1a1612;
}

h1 {
  color: #c64520;
}

a {
  background: #167a39;
  color: white;
  text-decoration: none;
  padding: 12px 18px;
}
PropriétéEffet, en français
colorCouleur du texte
backgroundCouleur de fond
font-familyLa police
paddingEspace intérieur (bouton plus cliquable)
text-decoration: noneEnlève le soulignement du lien
max-width + margin: autoColonne centrée, lisible

Bloc 2 · Live coding

On le fait ensemble (15 min)

Déroulement
  1. Crée un dossier vitrine sur le Bureau.
  2. Dedans, un fichier index.html (attention à l’extension, pas .txt).
  3. Colle le squelette. Sauvegarde.
  4. Clic droit → Ouvrir avec Chrome. Ils voient le titre.
  5. Ajoute un <p>, sauvegarde, recharge (F5). « Le fichier local : tu es client et serveur. »
  6. Ajoute le lien wa.me avec TON numéro en démo (ou un faux, puis chacun met le sien).
  7. Dans <style>, change fond, titre, bouton. Recharge.
Blocages classiques
  • Fichier nommé index.html.txt → affiche les extensions dans l’explorateur Windows.
  • Double-clic Word au lieu du navigateur → clic droit, ouvrir avec Chrome.
  • Accents bizarres → il manque charset="UTF-8".
  • Le CSS ne fait rien → la balise <style> est dans le body mal fermée, ou sélecteur mal tapé (h1 pas H1 dans le CSS, ça passe, mais .h1 non).
  • Le lien WhatsApp n’ouvre rien → + et espaces dans le numéro. Corriger.

Annexe B

Checklist anti-bug (à garder sous les yeux pendant le live coding)

  • Le fichier s’appelle bien index.html et pas index.html.txt.
  • <!DOCTYPE html> est la première ligne.
  • <meta charset="UTF-8" /> est dans le head.

  • Le numéro WhatsApp : indicatif + numéro, zéro espace, zéro plus.
