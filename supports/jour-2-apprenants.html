Partie 1 · Cours

1. Un algorithme, c’est une recette

Un algorithme, c’est une suite d’étapes claires pour résoudre un problème. Comme une recette de cuisine : dans l’ordre, sans sauter une ligne, jusqu’au résultat.

L’ordinateur ne « comprend » pas tes intentions. Il exécute exactement ce qui est écrit. Si la recette est floue, le plat est raté.

Le pseudo-code

La recette écrite en français structuré. Pas encore un langage de machine. Toi, un collègue, ou toi dans six mois : vous devez pouvoir la suivre.

Le programme

La même recette, traduite dans un langage que la machine exécute. Ce soir : Python. On ne code pas avant d’avoir la recette.

La règle du soir D’abord le pseudo-code. Ensuite Python. Si tu tapes du code sans recette, tu improvises — et tu te perds dès que ça se complique.

Les mots du pseudo-code, ce soir

MotSens
DEBUT / FINOn ouvre et on ferme la recette.
AFFICHERMontrer un message à l’écran.
LIREDemander une valeur et la ranger.
←Ranger une valeur dans une boîte (une variable).
SI … ALORSSi c’est vrai, faire ceci.
SINONSinon, faire cela.
FIN SILa décision est terminée.

Partie 1 · Cours

2. Dans l’ordre, une étape après l’autre

Analogie thé : tu ne verses pas l’eau avant d’avoir l’eau. Un algorithme avance ligne par ligne. 

DEBUT
  AFFICHER "Bonjour"
  AFFICHER "On commence."
FIN

Résultat, dans cet ordre : d’abord Bonjour, ensuite On commence.

Ranger dans une boîte

Une variable, c’est une boîte avec un nom. En pseudo-code, on écrit souvent prenom ← "Awa" : « mets Awa dans la boîte prenom ». 

DEBUT
  prenom ← "Awa"
  AFFICHER prenom
FIN

On affiche le contenu de la boîte, pas le mot « prenom ». À l’écran : Awa.

Lire, c’est écouter

DEBUT
  AFFICHER "Ton prénom ?"
  LIRE prenom
  AFFICHER "Bonjour"
  AFFICHER prenom
FIN

LIRE s’arrête et attend que quelqu’un tape une réponse. Ensuite seulement, on continue.

Décider : SI / SINON

Analogie feu : vert tu avances, rouge tu t’arrêtes. Une seule branche à la fois.

DEBUT
  AFFICHER "Ton âge ?"
  LIRE age
  SI age >= 18 ALORS
    AFFICHER "Tu peux voter."
  SINON
    AFFICHER "Pas encore."
  FIN SI
FIN
À bien verrouiller Le SI pose une question (vrai ou faux). Ce qui est indenté (en retrait) appartient à cette branche. FIN SI ferme la décision. Sans ça, on ne sait plus où la recette reprend.

Partie 2 · Cours

3. Python, c’est la traduction

Chaque mot du pseudo-code a un équivalent Python. Tu ne « devines » pas le code : tu traduis la recette.

Pseudo-codePython
AFFICHER "Bonjour"print("Bonjour")
prenom ← "Awa"prenom = "Awa"
LIRE prenomprenom = input("…")
SI age >= 18 ALORSif age >= 18:
SINONelse:
FIN SIle retrait s’arrête (plus de FIN SI)

Le premier mot : print

print("Bonjour")
print("On commence.")
  • Les guillemets entourent un texte.
  • Sans guillemets, Python cherche une variable.
  • print(Bonjour) → erreur NameError.

Le = range, le == pose la question

prenom = "Awa"
print("Bonjour", prenom)

En maths, = veut dire « égal ». En Python, = veut dire « mets ça dans la boîte ». Pour comparer : ==.

Deux types pour commencer

Texte · str

Guillemets. "20" + "1" donne "201" (collage).

Nombre · int

Sans guillemets. 20 + 1 donne 21 (calcul).

À retenir input rend toujours un texte. Pour calculer un prix : prix = int(input("Prix ? ")).

Partie 2 · Cours

4. De la recette au code, ligne à ligne

Même algorithme, deux écritures. Lis-les l’une sous l’autre.

Pseudo-code

DEBUT
  AFFICHER "Ton âge ?"
  LIRE age
  SI age >= 18 ALORS
    AFFICHER "Majeur"
  SINON
    AFFICHER "Mineur"
  FIN SI
FIN

Python

age = int(input("Ton âge ? "))
if age >= 18:
    print("Majeur")
else:
    print("Mineur")

Les deux-points : ouvrent le bloc. Ce qui est en retrait (4 espaces) appartient au if ou au else. C’est le FIN SI de Python : quand le retrait s’arrête, la décision est finie.

Les quatre erreurs du soir

ErreurRéflexe
SyntaxErrorParenthèse, deux-points ou guillemet manquant.
NameErrorVariable oubliée, ou texte sans guillemets.
IndentationErrorLe retrait sous le if manque.
ValueErrorint("Awa") : ce n’est pas un nombre.

Partie 3 · Mini-projet

Assez pour payer ?

Un problème du quotidien. D’abord la recette, ensuite le code. Fichier : python/decision.py.

Le problème

On demande le prix d’un article, puis la somme que tu as. Si tu as assez, le programme affiche le reste. Sinon, il affiche ce qui manque.

Étape A · le pseudo-code (non négociable)

Écris-le en commentaires en haut du fichier, avec #.

# DEBUT
#   AFFICHER "Prix de l'article ?"
#   LIRE prix
#   AFFICHER "Tu as combien ?"
#   LIRE argent
#   SI argent >= prix ALORS
#     reste ← argent - prix
#     AFFICHER "C'est bon. Il te reste :"
#     AFFICHER reste
#   SINON
#     manque ← prix - argent
#     AFFICHER "Pas assez. Il manque :"
#     AFFICHER manque
#   FIN SI
# FIN

Étape B · la traduction Python

prix = int(input("Prix de l'article ? "))
argent = int(input("Tu as combien ? "))

if argent >= prix:
    reste = argent - prix
    print("C'est bon. Il te reste :", reste)
else:
    manque = prix - argent
    print("Pas assez. Il manque :", manque)

Cahier des charges

  • Le fichier s’appelle decision.py.
  • Le pseudo-code est en commentaires en haut du fichier.
  • Deux input convertis avec int : prix et argent.
  • Un if / else : assez, ou pas assez.
  • Tu l’as lancé au moins deux fois : une fois « assez », une fois « pas assez ».
Exemple pour tester Prix 1500, argent 2000 → reste 500. Prix 1500, argent 800 → il manque 700.
