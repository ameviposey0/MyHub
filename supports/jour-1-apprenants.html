Partie 1 · Cours

1. Client et serveur

Sur Internet, presque tout est un dialogue entre deux rôles. L’un demande, l’autre répond. C’est le modèle client / serveur.

Le client

Le programme qui initie la demande. Exemples : Chrome, Firefox, l’app WhatsApp, ton téléphone. Il n’a pas la page en réserve : il la réclame.

Le serveur

Le programme (sur une machine souvent allumée en continu) qui attend les demandes et envoie la réponse : fichier HTML, image, vidéo, message.

Le dialogue, à chaque fois

  1. Le client ouvre une connexion vers le serveur.
  2. Il envoie une requête : « donne-moi telle ressource ».
  3. Le serveur traite, puis envoie une réponse (succès ou erreur).
  4. Le client reçoit et affiche (ou enregistre) le résultat.

Analogie resto : tu commandes (client), la cuisine prépare (serveur), le plateau arrive. Cuisine fermée → pas de réponse. Plat introuvable → 404. Commande OK → 200.

Points à bien verrouiller

  • Le client n’est pas « toi » : c’est le logiciel qui demande (le navigateur).
  • Le serveur n’est pas « Internet » : c’est une machine précise, avec une adresse.
  • Une même machine peut être les deux : aujourd’hui, ton PC est serveur (fichier local) et client (Chrome).
  • Un serveur peut répondre à des milliers de clients en même temps.
  • Sans serveur joignable, le plus bel HTML du monde n’arrive nulle part.
SituationClientServeur
Tu ouvres YouTubeChromeLes machines de YouTube
Tu envoies « salut » sur WhatsAppL’app sur ton téléphoneLes machines de WhatsApp
Tu ouvres index.html en localLe navigateurTon propre disque / ordi

Partie 1 · Cours

2. Nom de domaine

Une machine se trouve par une adresse IP (ex. 142.250.200.78). Quatre nombres entre 0 et 255, séparés par des points. C’est lisible pour une machine, pénible pour toi.

Le nom de domaine est le nom humain de ce lieu : google.com, whatsapp.com, wa.me. Comme le nom d’une boutique, au lieu du numéro de parcelle.

Anatomie d’un nom

Prends www.koffiedev.com (exemple) :

MorceauExempleRôle
Sous-domaine www Souvent le site web public. On peut avoir mail., api., etc.
Domaine koffiedev Le nom choisi, unique pour cette zone.
Extension (TLD) .com La « zone » : .com, .ci, .org, .edu…

On lit un domaine de droite à gauche : d’abord la zone (.com), puis le nom, puis éventuellement www.

Le DNS : l’annuaire du domaine

Le DNS (Domain Name System) traduit un nom en IP. Sans lui, tu devrais retenir des chiffres pour chaque site.

  1. Tu tapes google.com dans Chrome.
  2. Le client demande à un serveur DNS : « quelle IP pour ce nom ? »
  3. Le DNS répond, par exemple une adresse IPv4.
  4. Ensuite seulement, Chrome va frapper à cette IP.

Analogie taxi : tu dis « emmène-moi chez Awa ». Le taxi ne connaît pas Awa. Il demande l’adresse (DNS), puis il y va (connexion vers l’IP).

Si le DNS échoue Le navigateur affiche « introuvable » / « DNS_PROBE_FINISHED_NXDOMAIN ». Ce n’est pas encore le serveur web qui a parlé : le nom n’a pas d’IP connue.
À retenir Le domaine est un nom. L’IP est une adresse. Le DNS est le carnet d’adresses qui relie les deux.

3. Protocoles d’envoi

Un protocole est un accord : comment on parle, dans quel ordre, avec quels mots. Sans protocole commun, le client et le serveur ne se comprennent pas, comme deux personnes sans langue partagée.

Pour envoyer une page web, trois protocoles se relaient. Tu n’as pas à les configurer aujourd’hui, mais tu dois savoir qui fait quoi.

ProtocoleRôle, en une phraseQuand tu le vois
DNS Demande l’IP qui correspond au nom de domaine. Avant même d’ouvrir la page.
TCP Ouvre une connexion fiable et envoie les données sans les perdre. Invisible. C’est la route.
HTTP La langue de la requête et de la réponse web (« donne-moi la page »). Dans l’URL : http://
HTTPS HTTP + chiffrement. Personne au milieu ne lit facilement. Cadenas et https://

HTTP : la langue d’envoi de la page

HTTP = HyperText Transfer Protocol, le protocole de transfert de pages. Le client envoie une requête. Le plus courant aujourd’hui : GET (« donne-moi ce fichier »). 

GET /index.html HTTP/1.1
Host: exemple.com

Le serveur répond avec un code et le contenu :

HTTP/1.1 200 OK
Content-Type: text/html

<!DOCTYPE html> ...
CodeSignification
200OK. Voici la ressource.
301 / 302La page a déménagé. Va ailleurs.
403Interdit. Tu n’as pas le droit.
404Cette ressource n’existe pas chez moi.
500Le serveur a un problème interne.

HTTPS : le même envoi, dans une enveloppe

HTTPS = HTTP + chiffrement (souvent via TLS). Le S veut dire secure. Le dialogue est le même (GET, 200, 404), mais un regard sur le wifi du café ne lit pas le contenu en clair.

  • HTTP voyage souvent sur le port 80.
  • HTTPS voyage sur le port 443.
  • Un port, c’est la « porte » du serveur : l’IP est l’immeuble, le port est l’appartement.
Règle du bootcamp Pour une vitrine et un lien WhatsApp, on écrit toujours https://. On ne met jamais un mot de passe dans une page.

L’URL : protocole + domaine + ressource

L’URL assemble tout ce qu’on vient de voir. Exemple :

https://wa.me/22890123456?text=Bonjour

MorceauExempleRôle
Protocole d’envoihttps://Comment on parle au serveur (ici : HTTP chiffré).
Nom de domainewa.meLe nom. Le DNS le transforme en IP.
Chemin/22890123456Quelle ressource précise on GET.
Requête?text=BonjourUn paramètre. Ici, le message prérempli.

Le voyage complet, dans l’ordre

1. Nom tapé 2. DNS → IP 3. TCP + HTTPS 4. GET / réponse 5. Page dessinée
  1. Tu saisis le nom de domaine (ou tu cliques un lien).
  2. Le DNS donne l’adresse IP du serveur.
  3. TCP ouvre la connexion. HTTPS chiffre l’échange.
  4. Le client (navigateur) envoie un GET. Le serveur répond 200 + HTML, puis CSS, images.
  5. Le navigateur assemble et affiche. Toi tu vois « la page », pas l’IP.
Aujourd’hui Ta vitrine vivra d’abord sur ton ordinateur (un fichier). Client et serveur sont la même machine. Le modèle reste le même. On n’héberge pas encore en ligne.

Partie 2 · Cours

Écrire une page HTML et un peu de CSS

Une fois la page arrivée, encore faut-il la écrire. HTML = la structure (murs et pièces). CSS = l’apparence (peinture et rideaux).

Une balise

<p>Ceci est un paragraphe.</p>
  • <p> ouvre. </p> ferme. Le slash ferme.
  • Ce qu’il y a au milieu s’affiche à l’écran.
  • Écris les noms de balises en minuscules.

Le squelette de toute page

<!DOCTYPE html>
<html lang="fr">
  <head>
    <meta charset="UTF-8" />
    <title>Ma vitrine</title>
    <style>
      /* le CSS viendra ici */
    </style>
  </head>
  <body>
    <h1>Mon prénom</h1>
    <p>Une phrase sur moi.</p>
  </body>
</html>
LigneÀ quoi elle sert
<!DOCTYPE html>Dit au navigateur : c’est du HTML moderne.
lang="fr"Page en français.
<head>Infos pour le navigateur, pas le texte principal.
charset="UTF-8"Sans ça, les accents cassent.
<title>Le nom de l’onglet.
<body>Ce que tu vois.

Partie 3 · Mini-projet

Ta vitrine, avec un lien WhatsApp

Tu construis ta page. Fichier : vitrine/index.html. En l’ouvrant, ton navigateur est le client.

À avoir pour valider

  • Un fichier nommé index.html (pas .txt).
  • Un <h1> avec ton prénom (ou un pseudo).
  • Un paragraphe : qui tu es, en 2 ou 3 phrases.
  • Une liste : 3 choses que tu veux apprendre cette semaine.
  • Un lien https://wa.me/... vers ton numéro, texte : Bonjour, je viens de ta vitrine KoffieDev.
  • Au moins 3 règles CSS : fond, texte, bouton.

Si tu as le temps

  • Une photo photo.jpg dans le même dossier, avec un alt.
  • Un sous-titre <h2> « Me contacter ».

Colle ça, en changeant le numéro

https://wa.me/228VOTRENUMERO?text=Bonjour%2C%20je%20viens%20de%20ta%20vitrine%20KoffieDev

Exemple : 90 12 34 56 au Togo → 22890123456.

Si ça ne s’affiche pas
  • Le fichier s’appelle index.html.txt → affiche les extensions dans l’explorateur Windows.
  • Word s’ouvre au lieu de Chrome → clic droit, ouvrir avec le navigateur.
  • Accents bizarres → il manque charset="UTF-8".
  • WhatsApp n’ouvre rien → enlève le + et les espaces du numéro.
  • Tu as modifié le fichier mais l’écran n’a pas bougé → enregistre, puis F5.
